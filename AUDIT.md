# Portal audit - 10 November 2026

What this repo does: IECES Admin Portal is an Electron app for school administration, including learner records, MOOE receipts, media publication, and a shared BSP payment workspace. This review assumes school staff with multiple BSP clients editing one Supabase workspace.

## Must fix - addressed in 1.0.12 source

1. **Local records and tokens were readable files** (`electron/bsp/main.cjs`, `cloud-workspace.cjs`). Copying AppData exposed learners, payments, and refresh tokens. OS-backed encryption now covers app-managed caches, sessions, and recovery snapshots; portable backup exports require a password. Old installations continue writing plaintext until updated.
2. **Existing accounts could be linked without proving ownership** (`supabase/functions/report-register/index.ts`). An allowed email and arbitrary password could attach an app profile to an existing Auth identity. Existing accounts now require a successful password sign-in; lookup covers more than 1,000 users. New allowed accounts still register immediately without email confirmation by explicit user choice. Deploy the Edge Function for this fix to reach production.
3. **News authors could choose their own trusted role** (`supabase-news-role-approval.sql`). Sending `author_role: 'admin'` caused immediate approval. The new hardening migration derives trusted status from report access and restricts moderation. Without the migration, the original trigger remains vulnerable.
4. **Any authenticated account could use broad dashboard policies** (`supabase-enrollment-dashboard-access.sql`, `supabase-homepage-slides.sql`). A signed-in outsider could read school records or change homepage slides. The hardening migration replaces the named broad policies with report-allowlist checks. Other live policies and shared-app access still require inspection before claiming complete database isolation.
5. **Receipt uploads generated permanent public URLs** (`src/pages/MooePage.jsx`). A public bucket makes receipts readable to anyone with their URL. The app now stores paths and requests short-lived signed links; the migration makes the bucket private and restricts legacy grants. The server migration is required to revoke existing public access.
6. **Partial upload failures saved incomplete entries** (`src/pages/MooePage.jsx`). A rejected receipt upload was skipped while the entry reported success. Failed uploads now block saving, keep the form, and attempt cleanup of new files. A rejected database save preserves all uploaded receipts because a lost response may follow a committed write; network exceptions release the Save button. Unreferenced uploads can remain after an ambiguous failure.
7. **Malformed workspace units could be saved** (`supabase-bsp-workspace.sql`). Missing rosters or invalid archived years could pass top-level checks and break desktop loading. Unit/archive structure is now validated before saving; adult email edits also sync. Transaction rollback and receipt/revision rules remain intact. Apply the SQL update to fix production.
8. **Readable preview files and an unused hard-coded login remained** (`electron/print.cjs`, `electron/main.cjs`). Previews were written to temporary PDFs; an unused local login compared a bundled password. Previews now stay in memory, old previews are cleaned, and unused login/MOOE IPC is removed. Top-level navigation is blocked so external pages cannot inherit the preload API.
9. **Runtime/build dependencies had advisories** (`package-lock.json`). The full audit initially reported 14 findings, including critical/high issues. Compatible updates install Electron 44.10.2 and Vite 8.3.7; unused concurrently/wait-on dependencies were removed. Remaining moderate minimatch findings are in electron-builder's dependency tree; npm's suggested forced builder downgrade would be a breaking change. Build only trusted source until that chain is fixed.

10. **MOOE account options reused codes for unrelated expenses** (`src/pages/MooePage.jsx`). Opening the edit form revealed duplicate React keys: chalk allowance and office equipment both used `5020311002`, while other semi-expendable options had incorrect codes. The affected textbook/equipment/furniture options now follow DepEd's published FAR 1A; unknown historical codes remain selectable instead of silently changing saved records. Existing entries with ambiguous codes require accountant review. Source: https://www.deped.gov.ph/wp-content/uploads/Consolidated-FAR-No-1A-SAAODBOE-as-of-June-30-2025-Q2.pdf

## Validation and limits

Checks cover real Electron OS encryption/migration, failure preservation, wrong-password/tampered backups, password confirmation UI, BSP revision conflicts/recovery, registration ownership/input validation, SQL authorization/reruns, signed receipt rendering, and failed receipt deletion. The workflow runs checks before packaging. Tests do not change production data.

Verdict: confirmed source issues above are addressed; live SQL and Edge Function rollout remains necessary. File encryption does not make exports, printed documents, or authorized database queries end-to-end encrypted.

Not checked: production Supabase policies/configuration, live allowlist integrity, every shared application's policies, real payment records, physical printers, macOS/Linux key stores, code signing, and legal enforceability. The review went deepest on authentication, stored data, uploads, BSP transactions, and release configuration; it was not a line-by-line review of every screen or vendored PDF.js.
